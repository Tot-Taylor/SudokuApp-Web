## Engine parity and fixtures

The [JSON fixtures](../tests/fixtures/native-parity.json) record assertions from `Tests/SudokuSolverTests.swift`, `Tests/PuzzleUniquenessTests.swift`, and `Tests/GameFlowTests.swift`, plus the generator's clue and complexity bands. The points values are retained as native reference data. `Tests/DifficultyClassificationTests.swift` exercises the classification heuristic with a filled board of repeated 1s. A web fixture for Sudoku validity needs a legal board.

The Swift generator seeds itself using Swift's process-dependent `hashValue` and the standard library shuffle. Its seed-42 test compares two calls in the same process. Reproduce deterministic behavior within the web engine and verify the rule and difficulty fixtures. Exact seed-to-board parity between Swift and TypeScript remains unverified.

The web engine seeds three independent diagonal boxes, completes the grid with backtracking, and removes clues only while the result has a unique solution. It uses the native clue bands and requires naked or hidden singles to solve Easy and Medium. Hard and Expert must stall under those two strategies. Classification requires a legal, uniquely solvable puzzle with at least one editable cell. Each generation request is capped at 64 attempts and 500,000 search nodes and can run in a cancellable module worker.

## Web layout

The Home screen adds a noninteractive puzzle preview and uses two columns where desktop width permits. The game panel preserves the pink and gold board, heavier box boundaries, selected row and column, Eraser and single-row number pad. Keyboard arrows move focus across the grid, digits edit an editable cell, and Delete or Backspace erases. The clock appears at completion. The statistics table adds the approved per-tier totals and times. The Settings and Shop screens provide empty and placeholder states for the current feature set.
